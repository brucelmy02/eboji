# 交给 Codex 的本机安装流程

供用户明确请求安装或启动 eboji 时执行。面向使用者的说明见 [README](../README.md)，训练规则见 [Skill](../skills/eboji/SKILL.md)。目标是让用户进入现有网页，使用自己的本机 Codex 登录；无需先把 Skill 注册到个人技能目录。

当前主要验证平台为 macOS。本文是安装操作指引，尚无独立安装器、后台常驻服务或全新电脑端到端验收结果。不要将写好指引描述成已经发布或安装完成。

## 1. 获取完整项目

- 使用用户提供的真实仓库地址，在用户电脑上、当前任务允许写入的位置克隆完整项目。用户指定了目录时优先遵循；没有指定时可在当前可写工作目录下建立 `eboji`，并告知实际路径。不要克隆到临时目录作为长期安装位置。
- 如果当前任务已经打开这个项目，直接使用现有目录；同名目录已存在时先辨认内容，不覆盖、不重置。安装请求本身不意味着要更新已有源码或用户记录。
- 私有仓库需要用户已有的 GitHub 访问权限。下载失败时报告具体原因，不索取密码或令牌；可请用户提供完整项目压缩包。若只有云端执行环境，需要转到用户的本机任务，不能把云端回环地址当成本机安装成果。
- 安装后确认 `package.json`、`server.mjs`、`lib/`、`public/` 和 `skills/eboji/SKILL.md` 齐全。不要仅下载 Skill 文件夹。不要读取个人训练数据来验证安装。

## 2. 检查运行环境

- 读取 `package.json` 并检查 Node.js 的实际主版本，要求 22 或更新。项目没有第三方运行依赖，无需运行 `npm install`。
- Node.js 缺少或版本不足时，按 [官方安装说明](https://nodejs.org/en/download)和当前系统选择安装方式，遵守当前任务权限。需要用户完成图形安装或系统授权时，给出具体一步；已有可用版本则复用。
- Windows / Linux 尚未在本项目完成端到端验收，不能承诺直接使用 macOS 的 `start.command`；必须核实所选平台的启动和 CLI 调用方式。

## 3. 连接用户已有的 Codex

在项目根目录可以执行以下只读检查。它复用应用实际的检测逻辑，只输出可执行文件位置和连接摘要，不发起模型请求：

```sh
node --input-type=module -e 'import { findCodex, codexStatus } from "./lib/codex.mjs"; const binary = await findCodex(); console.log(JSON.stringify({ binary, ...await codexStatus(binary) }));'
```

- 项目的查找顺序为：已有 `CODEX_BIN`、系统可执行的 `codex`、macOS 上代码列出的桌面应用内置 CLI。优先使用现有工具，缺少时才按 [Codex 官方安装说明](https://learn.chatgpt.com/docs/cli)安装；不要为了安装 eboji 无故升级或替换可用 CLI。
- 对最终选定的同一个可执行文件检查版本和 `login status`。只报告是否登录及认证方式，不读取、复制或输出认证文件、令牌、环境变量中的密钥。
- 已通过 ChatGPT 登录则复用。未登录时用该可执行文件运行 `login`，让用户在官方浏览器页面完成登录，再检查一次。正在使用 Codex 聊天并不能单独证明网页选中的 CLI 已就绪。[官方登录说明](https://learn.chatgpt.com/docs/auth)
- 如果现有认证方式是 API Key，明确告知它与 ChatGPT 订阅额度不同。用户要求使用 ChatGPT 登录时引导其切换；不要静默改用 API 付费、填写开发者密钥或自动购买额度。
- 特殊路径确需 `CODEX_BIN` 时，在启动 eboji 的同一进程环境中传入已验证的绝对路径，并给用户保留可重复的启动方法。不要随意修改全局 shell 配置；当前程序不会自动加载 `.env`，仅写入 `.env` 不会生效。

## 4. 启动并检查网页

- 优先保留用户已有网址和端口，默认 `http://127.0.0.1:3000`。查到已有监听进程时，确认其启动文件和目录属于这份项目，再复用；仅凭端口或相同页面外观不能证明它是同一份安装。不要终止不明进程。
- 无已有服务时，在项目根目录用 `npm start` 启动，或在 macOS 使用 `start.command`。使用能保留运行会话的终端；短命令退出后服务是否仍在运行，需要实际检查。端口确被其他应用占用时选择空闲端口，说明改变网址会使用另一份浏览器本地存储。
- 检查首页和必要静态资源可访问，并调用实际地址下的 `GET /api/status`。只展示响应中的 `ready`、`message`；不向对话粘贴它附带的会话令牌。确认服务端选中的 CLI 与前一步检查的一致；切换 CLI 后需重新启动服务，但先确认没有正在处理的 AI 请求。
- `ready: true` 只证明应用找到 CLI 且登录状态检查成功，不证明远端调用成功、剩余额度充足或所有 CLI 参数兼容。默认验收到此为止；不要为了验收生成计划、提交反馈、采用预设或改写训练数据。
- 打开实际地址。在 Codex 桌面中可使用网页面板，否则使用系统浏览器。保持回环监听，不为安装方便开放公网或局域网访问。

## 5. 交付给用户

完成后用简短中文说明：

1. **打开哪里**：经过检查的可点击网址，以及网页是否已经打开。
2. **装在哪里**：实际项目目录。
3. **AI 状态**：登录检查通过，或尚需完成的具体步骤；说明是否尚未验证真实生成，不把预设可用说成 AI 可用。
4. **下次怎么打开**：同一目录的 `start.command` 或实际启动命令；若用了自定义端口或 `CODEX_BIN`，一并保留。说明需要保持哪个终端或运行会话开启，以及如何停止。

默认不新增开机自启、不安装全局 Skill、不部署云服务。沿用项目的动作库优先规则和记录保存方式。用户未完成登录时，可以先交付可用的预设网页，同时明确 AI 连接仍待完成。
